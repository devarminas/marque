# 0004. Jump ballistic constants

## Status

Accepted (M13e / ARM-237). Implements jump under `docs/adr/0001-movement-authority.md` §11–12 and wire names in `docs/adr/0003-movement-wire.md`.

## Decision

1. **Jump edge.** A `move` sample with `jump: true` is a grounded-only impulse. While `y <= 0` and vertical speed `vy <= 0`, the server sets `vy = JumpSpeed`. The wish `dx`/`dz` on the same sample still applies.
2. **Ballistic integrate.** Each tick: `vy -= Gravity * dt`, `y += vy * dt`, with `dt = TickDuration`. When `y` crosses or reaches `0`, land at `y = 0`, `vy = 0`. Flat ground only. No double jump, climb, swim, or walk-under bridges.
3. **Constants** (world units, seconds):

| Name | Value | Role |
|---|---|---|
| `JumpSpeed` | `5.0` | Upward `vy` on a legal jump edge |
| `Gravity` | `20.0` | Downward acceleration while airborne |

4. **Illegal mid-air jump.** `jump: true` while not grounded is refused with `RejectReason` `illegal_sample`, `Re` `move`, connection kept. Wish on that sample still applies. Pose facts stay refused at the wire denylist as today.
5. **Pose.** Authoritative `y` continues on `pose` / `welcome` / `spawn` / `PlayerState`. `vy` is server-private; clients that predict use the same constants and re-derive from the jump edge plus reconciliation to server `y`.

## Consequences

- Server and predicting client share these numbers. Changing them needs this ADR amended.
- Ability locomotion (ARM-238) may later gate jump; it does not replace this integrator.

## Non-goals

- Climbing, swimming, double jump, bridges you walk under.
- Air-control curves beyond the existing ground wish while airborne.
- New uplink fields or a standalone jump ability type.
